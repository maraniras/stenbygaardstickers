# Stenbygaard Stickers

Kort over stickers (med Stenbygaard-hovedet) sat op rundt om i verden. Talk to the user in Danish; the app UI is Danish. Mobile first, deployed on Vercel.

- Nuxt 4, `ssr: false`. Pages: `/` map (Leaflet + markercluster; OSM tiles by default, toggle to Esri World Imagery aerial photo + labels, `app/utils/basemap.ts`, choice saved in localStorage and shared with the upload map picker), `/liste` timeline + stats, `/sticker/[id]` detail with gallery, `/upload` (round + button next to the refresh button on map and list), `/admin` + `/admin/[id]` (small "Admin" link at the bottom of `/liste`).
- **Stickers live in the database**, not the repo: Redis hash `stickers` (id → JSON with `status: 'pending' | 'approved'`), via `server/utils/stickers.ts`. The app fetches approved ones from `/api/stickers` with `useStickers()`; `app.vue` waits for the first fetch, after that it refetches when the app becomes visible/focused and every 60 s (only replaces the list if it changed; the map keeps its view). Types are in `shared/types/sticker.ts`.
- `app/data/stickers/*.json` are only **seed data**: each file is copied into Redis once (ids remembered in set `stickers:seeded`), so later edits/deletes in admin win. A new JSON file is picked up on the next deploy. Repo media stays in `public/media/<id>/`.
- **Upload flow**: anyone with the app code can submit on `/upload` (map picker with geolocation, Google Maps-style coordinate field, name autocomplete, images compressed to webp in the browser (the EXIF date of the first photo pre-fills the date unless it was edited; `photoDate` in `app/utils/upload.ts`, lazy-loaded `exifr`), videos uploaded as-is ≤100 MB with a poster frame). Submissions are `pending` until approved on `/admin`, where title, description, names, place, city/country and media can be edited. Rejecting/deleting also deletes uploaded media.
- Uploaded media goes straight from the browser to **Vercel Blob** (a *public* store). New stores only set `BLOB_STORE_ID` and authenticate with OIDC (`x-vercel-oidc-token` header) → presigned uploads via `issueSignedToken`/`uploadPresigned`; older stores with `BLOB_READ_WRITE_TOKEN` use `handleUpload`/`upload`. Both in `server/api/upload.post.ts`. Without the token in dev, files go to `.data/` and are served from `/api/media/<file>`.
- **Dev site**: branch `dev` → Vercel Preview (`stenbygaardstickers-git-dev-mathiaskirras-projects.vercel.app`, behind Vercel login). Preview shares the Redis DB and Blob store with prod but is isolated: `redis()` prefixes every key with `dev:` when `VERCEL_ENV === 'preview'`, uploads/backups go to the Blob folder `dev/`, and dev only deletes blobs under `dev/`. On first start dev copies approved stickers from prod's public `/api/stickers` (key `dev:stickers:prodcopy`). Work on `dev`, merge to `main` for prod. `ADMIN_PASSWORD` must also be enabled for Preview for admin on dev.
- **Backup**: Vercel Cron (`vercel.json`, daily 03:00 UTC) calls `/api/cron/backup`, which writes all stickers (incl. pending) + all ratings as JSON to Blob `backups/` (random suffix) and keeps the newest 30 (`server/utils/backup.ts`). Protected by `CRON_SECRET` if set, otherwise max one backup per 20 h. Admin page has "Tag backup nu", a download and the list. Locally backups go to `.data/`.
- **Link previews**: `server/plugins/og-tags.ts` injects og:/twitter: meta tags into the SPA HTML (`render:html` hook) – sticker title, place, description and first image on `/sticker/<id>`, generic site text elsewhere. The sticker page has a share button (Web Share API, falls back to copying the link).
- **Notifications for everyone**: when a sticker is approved for the first time, `/api/admin/stickers/[id]` (PUT) notifies the public list (Redis hash `push:all`, routes `/api/push`). `PushPrompt.vue` asks once after the update (own in-app box, the browser prompt only opens on a tap; remembered in localStorage `stenbygaard-push-asked`), afterwards only the bell (`NotifyButton.vue`) on `/liste`. iPhone in Safari gets a "add to home screen" hint. Shared client logic in `usePush.ts` (lists `admin` and `all`).
- **Badge numbers**: the user refers to badges as x1, x2 … – the fixed list is `docs/badges.md`. A new badge gets the next free number there (never renumber).
- **Profile and badges**: `/person/<navn>` shows stats, badges in tabs Opnået/Mangler (`app/utils/badges.ts`, medals in `BadgeMedal.vue`) and countries. Tiered badges have a name per level (e.g. partner: Makker → Venner → BFF → Dynamisk Duo → Sindssyg Ægte venner "med <navn>"), incl. per-continent badges (`app/utils/continents.ts`) and Hovedstadsjæger (within 25 km of a capital, `app/utils/capitals.ts`). A badge can set `flag` to show a flag image instead of an emoji (Windows cannot render flag emojis). Tapping a medal opens `BadgeSheet.vue`: with `badgesFor(..., { history: true })` the person's stickers are replayed in date order to find `earnedAt`/`earnedWith` and each level's `reachedAt`; also `progress` for singles and `holders` for records. Singles (seasons, Stamkunde, Grænsehopper, Original = first 5 …) and records (farthest, north, south, crowd favourite = highest avg → most votes → placed first, and "Årets Dengse <år>" per calendar year from 2026, locked when the year ends; ties → whoever reached the count first). Badge counts show on the people chips in `/liste`.
- **Install prompt** (`InstallPrompt.vue`, `useInstall.ts`): once for non-installed users – iPhone Safari gets "Del → Føj til hjemmeskærm" instructions, Android/Chrome a real Install button via `beforeinstallprompt`. "Installer appen" link at the bottom of `/liste`. The push prompt waits until the install box is closed.
- **Points and levels** (`app/utils/badges.ts`, `LevelCard.vue`): every badge gives points (`SINGLE_POINTS`, `TIER_POINTS` per level, Pioner 3 per country, Årets Dengse 10 once the year is over; live records give no points). Levels 1–10 in `LEVELS` (0/10/25/45/75/115/170/240/330/450) with titles Nybegynder … Stenbygaard-legende. Shown with `LevelBadge.vue` (Garmin-style hexagon, colour per level, gold with a star at 10) on the profile, in the level list and next to names on `/liste`, plus points in the badge modal. Europa badge does not count Denmark. Max ≈ 970 + Pioner + years.
- **Countries** (`/lande`, from the "lande" box on `/liste`): world map from `world-atlas` 110m + `topojson-client`, numeric ids mapped with `i18n-iso-countries`, lazy-loaded.
- **Admin notifications**: Web Push. `/admin` has a "Få besked om nye stickers" switch (`AdminPush.vue`) that registers `public/sw.js` (push + notificationclick only, no caching) and stores the subscription in Redis hash `push:subs`. VAPID keys are generated on first use and stored in Redis `push:vapid` (`server/utils/push.ts`). `/api/submissions` notifies all admins; dead subscriptions (404/410) are removed. Works on Android/desktop; iPhone only from the home screen (iOS 16.4+).
- **Admin login**: `ADMIN_PASSWORD` env var on Vercel (httpOnly cookie with an HMAC of it). In dev without it the password is `admin`.
- **Adding a sticker yourself** (the user gives coordinate, title, date, names, description and media): either ask them to use `/upload` + `/admin`, or run
  `node scripts/add-sticker.mjs --lat <lat> --lng <lng> --title "…" --date YYYY-MM-DD --by "Navn1, Navn2" --desc "…" <filer…>`.
  It reverse-geocodes city/country with Nominatim (Danish names), converts images to webp (max 1600px) and videos to mp4 (H.264, max 1080px, ≤15 s) with a poster. Check the printed city; override with `--city/--country/--cc` if wrong. Then commit and push → Vercel deploys and the new file is seeded. Changing an already seeded JSON file does nothing – edit it in `/admin` instead.
- **Users (optional, no sign-up)**: `/mig` (third bottom-nav tab "Mig"). You type or pick your name and it is locked to the device: the server returns a random token (localStorage `stenbygaard-user-token`, sent as header `x-user-token`) and stores only its SHA-256 (`server/utils/users.ts`, routes `/api/me`, `/api/me/code`, `/api/me/pair`, `/api/users`). Names are unique case-insensitively; picking a name that is on stickers uses that spelling, so the profile/badges are yours. More devices: "Vis kode" on `/mig` gives a 6-digit code (10 min, single use, max 10 wrong tries per IP per 10 min) to enter under "Jeg har en kode". Logging out the last device frees the name; admin can free a name in `AdminUsers.vue`. Redis: hash `users` (lower-case name → record with device hashes), hash `user-tokens`, `user-code:<code>`, `user-pairfail:<ip>`. `useUser()` gives `name`, `isMe()`, `setAvatar()`; the profile shows "Det er dig". **Profile pictures**: on `/mig`, cropped to a 400×400 centre square in the browser (`uploadAvatar` in `app/utils/upload.ts`), uploaded to Blob `avatars/` (dev: `dev/avatars/`), saved with `PUT /api/me/avatar` (`isAvatarFile` check, old file deleted; also deleted when the name is freed). `/api/users` returns `{ name, avatar? }`; `useUsers()` + `UserAvatar.vue` (picture or initial, styled by the parent's class) are used wherever a name has an initial bubble. Logged in, `/upload` pre-fills "Sat op af" with your own name. Ratings are still per device (not yet per user). **Badge notifications**: badge rules live in `shared/utils/badges.ts` (with `continents`, `capitals`, `seasons` and `sticker.ts`: `Sticker`, `distanceKm`, `withDistance`, `sameName`) so the server computes exactly what the app shows. `server/utils/badge-push.ts` `syncBadges()` runs after admin approve/edit/delete and after every rating (`event.waitUntil`): per user it diffs `earnedKeys()` (one key per tier level, e.g. `cities:2`, otherwise the badge id) against `user.badgeKeys` and pushes to that user's devices (`device.push`, set via `/api/me/push` – automatically when the browser already has permission, unless switched off on `/mig`): new badges/levels (more than 3 → one grouped message) and lost records ("😱 X har taget din rekord"). The same key is pushed at most once per 24 h (`notifiedAt`). Notification URL `/person/<navn>?badge=<id>` opens the badge sheet and marks it seen (`/api/me/seen` → `seenKeys`). `BadgePopup.vue` shows earned-but-unseen badges ("Ny badge!") when the app opens, waits while a badge sheet is open. Before that it shows **"Level op!"** with confetti (`shootConfetti()` in `useConfetti.ts`, lazy `canvas-confetti`) when the level from `levelFor(totalPoints(...))` is higher than the highest seen `level:<n>` key in `seenKeys` (the first time the current level is stored silently). On first login (or first `/api/me` after this feature) everything already earned counts as seen. Planned next: currency/daily games (see memory).
- **Notification settings** (`/notifikationer`, from the bell on `/liste` and "Notifikationer" on `/mig`): a main switch for this device (push list `all` + `device.push` for logged-in users) and one switch per type from `NOTIFY_TYPES` in `shared/utils/notify.ts` (`stickers`, `badges`, `levels`, `records`, `tags`, `replies`, `comments`, `likes`), saved on the user (`user.notify`, `PUT /api/me/notify`, missing = on, `wants()`), so they apply to all the user's devices. Without a name only "Nye stickers" is shown. The server checks the type in `notifyUser(name, msg, type)`, `syncBadges()` (badges/records/levels) and `comment-notify.ts` (a recipient who muted the first-priority type still gets the next one); new-sticker pushes skip devices of users who muted `stickers` (`mutedEndpoints`). **Level-up push** "⬆️ Level 3: Gadeplakat": `syncBadges()` compares `levelFor(totalPoints())` with `user.level` (set silently the first time). Admin's "nye indsendte stickers" stays on `/admin`.
- Users can click a name → `/person/<navn>` (list) and `/?by=<navn>` (map filter). Write the sticker description funny/sarcastic in Danish if the user only gives a start; Emil is the face on the sticker.
- **👍 ratings** (were stars until Oct 2026; Redis keys `rating:<id>`/`rated` and badge ids `stardust`/`fivestar` kept): 1–5 👍 per device (random id in localStorage, `deviceId()` in `useRatings.ts`), tapping your current number again removes it (`value: 0`). Logged-in users cannot rate stickers with their own name (server 403 + `StarRating.vue` shows "Din sticker") – anonymous devices cannot be checked. `server/api/ratings.*` + `server/utils/ratings.ts`. Redis is shared with the stickers (`server/utils/redis.ts`, env vars `KV_REST_API_URL`/`KV_REST_API_TOKEN` or `UPSTASH_REDIS_REST_*`); without them in production the ratings API returns 503 and the rating is hidden. In dev both fall back to Nitro storage in `.data/`.
- **Comments** (`CommentsSection.vue`, `CommentItem.vue`, `CommentComposer.vue`; server `server/utils/comments.ts`, `comment-notify.ts`, routes `/api/comments*`, `/api/comment-stats`): everyone can read and 👍, only users with a name can write. One reply level (a reply to a reply goes into the same thread, prefilled `@author`). `@Name` autocomplete from registered users, never yourself; the server re-parses mentions (`findMentions`, longest name first). Edit own comment for 10 min (`COMMENT_EDIT_MS`, shared/utils/comments.ts), delete own any time; admin can delete all (deleting a top comment deletes its replies; deleting a sticker deletes its comments). 👍 on comments: per user (`u:<name>`) or anonymous device (`d:<id>`), not on your own; long-press the 👍 to see names + "X anonyme" (the author gets a "Se hvem" link). Notifications (one per recipient per comment, priority tag > reply > own sticker): "🏷️ X har tagget dig", "↩️ X har svaret dig", "💬 Ny kommentar på <titel>", "👍 X (og N andre) synes godt om din kommentar" (max once per hour per comment). URL `/sticker/<id>?comment=<cid>` scrolls to and highlights it. Comment badges (`commenter`, `tagged`, tier `likes` 1/5/10/25/50 total, `hit` 5 and `viral` 10 on one comment) come from `commentStats()` passed as `badgesFor(..., { comments })` – client via `useCommentStats()`. Backups include comments and their likes. Redis: `comments:<stickerId>` hash, `commented` set, `comment-likes:<cid>` hash.
- Design: v2 (light, glass, soft shadows). The first design (thick black outlines, yellow) is git tag `design-v1` if the user wants to go back.
- **Emils rejse** (`app/utils/journey.ts`): play button on the map animates a dotted arc from home (`JOURNEY_START` 57.042237, 9.914973) to each visible sticker in date order with a flying head, landing pins and a progress card (respects the person filter). The normal pins/cluster are hidden while it plays.
- **Seasonal themes** (`useTheme.ts`): Easter (Wednesday before Palm Sunday – Tuesday after Easter Monday = Easter Sunday −11 … +2 days, computed with the Gregorian Easter algorithm in `easterSunday`), Halloween 26 Oct–1 Nov, Christmas 20 Nov–31 Dec, otherwise normal. Easter has bunny ears (`public/theme/bunny-ears.svg`), floating eggs and a chick. Sets `data-theme` on `<html>`; colors via CSS variables in `main.css` (`--accent`, `--accent-light`, `--on-accent`, `--ink` for dark surfaces, `--title`, `--surface*`, `--cluster`, map tile filter, top glow), hats on pins (`.pin::after`; the head and hat sit in `.pin` so they scale together) (`public/theme/*.svg`), bats/snow in `ThemeDecor.vue`. The date alone decides the theme (no manual switch).
- Distances are measured from Aalborg (`AALBORG` in `app/utils/stickers.ts`).
- Code lock: `emileric` (`app/composables/useUnlock.ts`), client-side only.
- Icons: `npm run icons` regenerates favicon/PWA icons/marker from `branding/logo.png`.
- Build assets live under `/_app/` (`app.buildAssetsDir`), not `/_nuxt/`: some browsers cached the SPA HTML under old `/_nuxt/` chunk names (a missing chunk during a deploy switch got the HTML with the immutable cache header → blank app). `server/middleware/missing-assets.ts` now answers missing build files with an uncached 404.
- **Hvad er nyt** (`/nyheder`, link at the bottom of `/liste`): versions and short user-facing notes in `app/utils/changelog.ts` (newest first, no admin/backup items). Add a note when something users can notice ships, and set `date` when it reaches prod.
- **App updates**: `app/plugins/update.client.ts` compares `useRuntimeConfig().app.buildId` with `/api/version` when the app becomes visible/focused (reloads by itself, except on `/upload` and `/admin`) and every 5 min (shows `UpdateToast.vue` "Ny version klar · Opdater").
- `npx nuxi typecheck` must pass.
