## Banana economy and daily games (dev, Oct 2026)

- `/spil` is the hub (`spil.vue` is a NuxtPage wrapper); `/spil/byen`, `/spil/hjulet`, `/spil/bananer` are playable games/private ledger. `useEconomy()` fetches authoritative availability, own wallet and public balance/stats; updates on foreground, every 60 seconds, account change and the 04:00 Danish day boundary. Navbar indicator stays until both games are finished. Profile wallet and leaderboard banana sort use real balances. Both daily game cards are entire native NuxtLinks (no nested links), including artwork and text.
- Rules: `shared/utils/economy.ts`, `game-day.ts`, `economy-badges.ts`. Welcome250 once; DK250, abroad500–5000 (0/1000/2000/4000/6000/8000km →500/750/1250/2500/3750/5000, nearest50). Each credited name gets full reward on approval, also historical stickers. Ordinary badge points×20 per new step; Pioner60/country; loseable records0; year winner200 after year-end Copenhagen time. New explicit badge rewards are never also paid via XP. Cosmetic/physical sticker shop, casino and stocks are later work.
- `economy` Redis hash stores per-account balance, permanent claims, peak balance, badge milestones, recent250 transactions, lifetime game stats and last35 days of runs. `mutateEconomy` atomically compares and sets whole record using Lua; `redisEval` explicitly prefixes KEYS in preview. Local unstorage queue serializes by account and supports its automatic JSON deserialization. Never reset claims/stats on logout or trim them with game days. Backups include full economy and game secret.
- API: authenticated GET `/api/economy/me`; public `/api/economy/public` exposes balances/peak/stats/milestones only. POST `/api/games/city/guess` and `/api/games/wheel` require current day and user token, validate server-side, commit run and payout together, and invoke badge push. Repeats cannot reroll or pay twice. Approval/comment/rating badge sync also settles economies. First wallet access migrates old rewards idempotently.
- City:192 capital coordinates/names in server-only `server/data/daily-cities.json` (sources/license in SOURCES.md),32 six-city groups shuffled with private persistent `games:secret`; all options repeat only after32 days. `games:challenge:<day>` pins the day's generated question for40 days on Redis. No answer/coords in unfinished API responses/client bundle. Authenticated `/api/games/city/image` proxies Esri aerials, strips metadata with sharp, picks zoom from saved attempts, caches by day/step. Image failure consumes no guess. Six choices, five attempts, 50/40/30/20/10 reward. A failed round breaks win streak.
- Wheel: cryptographic server draw; 0/1/10/25/50/100/daily-jackpot prizes with35/10/30/18/5/1.5/0.5% odds. Zero outcome is also saved, so refresh never rerolls. One banana breaks nit sequence. The decorative wheel has 20 equal slots (7 Miv), independent of unchanged server odds; exact probabilities are shown in the details. A winning value lands on a randomly chosen matching visual slot. Nine turns over6.5seconds with gradual deceleration; reduced-motion supported. Arcade cabinet design with brass rim,20 chasing bulbs during spin, gold SVG pointer, jackpot marquee, pastel prize palette, Emil medallion (no text inside) and matching gold free-spin button. Uses CSS/SVG and existing Fluent banana art; no extra media dependencies. WheelFace.vue is shared by the full game and the transparent compact illustration on the games hub, so both wheels use the same artwork and palette. Badge popup waits for spin animation.
